# Tail-Me

Social sports-betting app for one friend group: users post straight / parlay / ladder slips, friends view and "tail" them (open the poster's sportsbook with the bet prefilled). $5/mo Stripe subscription pays for The Odds API.

## Stack
- Client: React 19 + TypeScript, react-router 7, Tailwind 3, bundled by webpack + Babel (`src/client`)
- Server: Express 5 (`src/server`), compiled by `tsc -p tsconfig.prod.json` to `dist/server`
- Shared: `src/shared` — odds math (`odds.ts`) and zod post schemas/types (`posts.ts`), used by both client and server
- DB: Supabase Postgres via **Prisma 7** (`prisma/schema.prisma`, config in `prisma.config.ts`, client generated to `src/generated/prisma`, gitignored)
- Auth: Supabase Auth; images will use Supabase Storage

## Commands
- `npm run start:dev` — API on :8080 (nodemon + ts-node); `npm run dev` — client on :4000, proxies `/api` to :8080
- `npm run prod` — build server + client, serve both from :8080
- `npm test` (vitest), `npm run typecheck`, `npm run lint`
- `npm run db:migrate` (migrate dev + generate), `db:deploy`, `db:seed`, `db:studio`
- `npm run db:demo` — fake friends + slips for UI work (re-runnable; `-- --clear` removes them)
- `npm run admin:set -- <username> [true|false]`, `npm run dev:subscribe -- <username> [ACTIVE|NONE]`

## Rules & decisions
- Paywall: free users can view + tail. Posting and anything that hits the Odds API require `requireSubscription`; client mirrors it with `useAuth().isSubscribed`. Both use `hasAccess` in `shared/billing.ts`: admins, ACTIVE / TRIALING / PAST_DUE (Stripe retrying the card), or everyone before `FREE_UNTIL` (launch promo, free through Oct 31 CT).
- Billing (`routes/billing.ts`, `server/stripe.ts`, page `/billing`): Stripe-hosted Checkout + billing portal only, so no card data or Stripe.js on our side. Status changes only via `syncCustomer`, which re-reads the customer's subscriptions from Stripe (never trusts event payloads or the success URL); called by the signed webhook `POST /api/billing/webhook` (mounted before `express.json` for the raw body, deduped in `StripeEvent`) and by `POST /api/billing/sync` on return from Checkout. Price comes from `STRIPE_PRICE_ID`, redirects from `APP_URL` (not the Host header). Subscribing during the promo sets a trial ending at `FREE_UNTIL` (`promoTrialEnd`). Webhook events needed: `checkout.session.completed`, `customer.subscription.created/updated/deleted`.
- Signed-out visitors at `/` see the marketing page (`pages/Landing.tsx`, rendered by `RequireAuth`); other protected routes still redirect to `/login`. Its slips are static mockups, so it makes no API calls.
- First-visit tour (`components/Tutorial.tsx`): a 7-step card carousel (feed, Tail, posting, ladders, group parlays, series, auto-grading) that `AppLayout` opens until `User.tutorialSeenAt` is set (`POST /api/me/tutorial`, on finish or skip); Settings → Help → "Take the tour" replays it (`openTour` on the layout context). Keep its copy in step with features. Empty spots show faded, "Example"-tagged placeholders (`components/Placeholders.tsx`): a sample straight, ladder and group parlay on an empty feed, ghost leaderboard rows, a 0-0 group parlay panel.
- Signup is server-side only (`POST /api/auth/signup`) so the shared `SIGNUP_PASSCODE` can't be skipped; Supabase public signups are meant to be disabled.
- API auth: client sends Supabase access token as `Authorization: Bearer`; `requireAuth` verifies it and loads the Prisma `User` into `req.user`.
- Users have required `fullName` + unique `username`; show both.
- Post model: Post -> Bet[] -> BetLeg[]. Straight/parlay = 1 bet; ladder = 1 single-leg bet per rung (same pick, climbing lines). Units on bets; straight/parlay slips show "$10 pays $X" (`payout(10, decimalOdds)`; $0 once lost, $10 back on push/void). Ladders show payouts in the poster's units plus an "N/M hit" count. Parlay `americanOdds` may be the book's slip price (same-game parlays) instead of multiplied legs.
- Bets grade themselves (`src/server/grading.ts`, every 10 min, started in `index.ts`; `DISABLE_GRADER=true` turns it off). Pending legs on games that started 2h+ ago (up to 7 days) are matched to ESPN's free, unofficial scoreboard (`src/server/espn.ts`): game lines grade from the final score, props from the box score (`BetLeg.actual` keeps the stat, shown as "Final 278"). Rules + name matching live in `shared/grading.ts`. Leg results roll up via `betResultFromLegs` (parlays use `groupResult`). Postponed/canceled games void. Unmatched games or players (incl. players who sat) stay pending for a person. `gradedBy` (AUTO/MANUAL) on Bet and BetLeg: the grader never touches MANUAL; filter with `OR [null, AUTO]`, not `not: 'MANUAL'` (NULLs). Manual override is subtle on purpose: the ⋯ menu's "Change result" (`SlipMenu`) for personal slips, a small pencil on group legs. One shared feed.
- Slip status chips (`shared/live.ts`, `SlipParts`): settled bets show their result; unsettled ones show LIVE while the game is on (once on the slip when every leg is the same game, else per leg beside the game), PENDING only once the game is over but ungraded, and nothing before kickoff. A game counts as over when the grader marked its `Event` completed or 5h after start (`MAX_GAME_MS`). Legs carry `eventId`/`startsAt`/`gameFinal` for this; cards tick once a minute (`useNow`). Group legs show a green check / red X on the right as their one result mark.
- Deleting can't clean up a record (`deleteRule` in `shared/posts.ts`): settled slips are soft-deleted (hidden from feeds, can't be re-graded) and still count in every stat (profiles, streaks, earners, calendar, series, group record); unsettled slips can only be deleted within `DELETE_GRACE_MINUTES` (15) of posting, which removes them entirely; unlocked group parlays can always be removed. Stats queries must not filter on `deletedAt`; feed/list queries must. The delete dialog explains this first. Author actions (move to series, delete) live in the card's ⋯ menu (`SlipMenu`).
- The site runs on Central time (`shared/time.ts`, `America/Chicago`): every shown date/time and every day bucket (calendar, "Today") uses it regardless of the viewer's device; clock times carry a "CT" label. Format with `inSiteZone(...)`, never bare `toLocale*`; the lock-by input uses `toSiteInput` / `fromSiteInput`.
- Stats (`src/shared/stats.ts`, served by `GET /api/users/:username?range=7d|30d|all`) count bets: straight/parlay = 1, every ladder rung is its own W/L. Voids don't count. Multi-league parlays count overall and per type but under no league. Pushes don't break streaks; current streak ignores the date range. Computed in memory per request (fine at friend-group size).
- Profiles live at `/u/:username`: date range is the only filter; per-type / per-league / tailing stats are compact rows in a sticky side column on `lg`; on smaller screens they're one tabbed card (Bet type, the default / Series / League / Tailing) above the slips. `AppLayout` main is `max-w-5xl`; each page sets its own column width (feed = `max-w-2xl`). `GET /api/posts?author=&range=` feeds their slip list. `PATCH /api/me` edits name + bio (username is fixed). Settings (`/settings`, `pages/Settings.tsx`) is the one place to edit your account: name + bio, email + change password (re-checks the current password with Supabase, then `updateUser`), dark mode, a plan summary linking to `/billing`, Take the tour, sign out. The account menus hold Profile, Settings, the dark mode switch and Sign out; the profile page's "Edit profile" links there.
- Social (`routes/social.ts`, mounted at `/api`): `GET /posts/:id/tails` (who tailed, once per person), `POST /posts/:id/reactions {emoji}` toggles (fixed set in `shared/social.ts`), comments `GET/POST /posts/:id/comments`, `DELETE /comments/:id` (own, or admin), `PUT /comments/:id/vote {value: 1|-1|0}` (`CommentVote` table). Free users can do all of it.
- Badges (`shared/badges.ts`): poster streak chip at W3+ (`FeedPost.author.streak`, all-time), win tiers by the longest price that hit (`WIN_TIERS`: Nice hit +200 green, Cashed +400 gold, Big score +900 violet, Jackpot +2400 pink with a shimmer; a clean ladder sweep shows at least Cashed) set the card border and a banner (`TIER_STYLES`, `WinBanner` in `SlipSocial`), "🔒 Group lock" at 3+ tails (`CrowdChip`). Cards show the latest 3 tailers' faces + count (`FeedPost.tailers`, distinct people). Thresholds live there. Settling returns the updated `FeedPost` so streaks refresh.
- Feed sidebar (`GET /api/community?tz=&month=YYYY-MM`, on `lg` the side column holds top earners, group parlays (`CommunityHighlights stacked`), who's hot and the calendar; below `lg` top earners, the group record and the calendar are one tabbed card above the slips (`CommunityTabs`); one fetch via `useCommunityStats`): "Who's hot" (W3+ streaks), top 3 earners over 7 days (only people up units), month calendar of group net units by post day in the viewer's time zone.
- Feed left column (`xl` only, `components/ActivePanels.tsx`, `GET /api/posts/active`, refreshed every 2 min): unsettled group parlays (open / locked / LIVE) and "Live now" (personal slips with a game on, same rule as LIVE tags). Clicking a row scrolls the feed to the slip (`PostList focusId` pages down up to 10 pages, `lib/scrollToSlip` flashes a ring; cards carry `id="slip-<postId>"`). Below `xl` the group parlays panel sits above the slips only when there are any.
- Group parlays (`GROUP_PARLAY` post, one Bet): each person adds one leg (`BetLeg.addedById`, unique per bet) via `POST /posts/:id/legs` until `Post.lockAt` passes or the creator hits `POST /posts/:id/lock` (needs 2+ legs). Legs come from the live picker only (one book). The creator can tick "This game only" (`Post.groupEventId` / `groupEventLabel`, from their leg); joins must match that event id; the picker opens straight into that game with no way back to other games (the server check is the fail-safe). Same-game group parlays show the legs multiplied as "est." until the creator enters the book's price after lock (`PUT /posts/:id/price`); `hasBookPrice` tells them apart (legs are fixed once locked). Once locked anyone, creator included, can place it (the tail route). Legs are graded one by one (`PATCH /posts/legs/:legId`, owner or creator); `groupResult` derives the bet. They never count toward personal stats, streaks, earners or the calendar (`PostType` in `shared/stats.ts` excludes them; filter with `POST_TYPES` / `isPersonalType`). The sidebar shows the group record and each person's legs hit / busted. Adding legs needs a subscription; placing doesn't.
- Series (`Series` table, `Post.seriesId`, `shared/series.ts`, `routes/series.ts`): a user's named run of personal slips (never group parlays), picked on the slip review step or created there. Listed in the profile side column (`SeriesPanel`), each with a page at `/u/:username/s/:id` showing its record (same stats math as profiles) and slips (`GET /posts?series=`). Names unique per owner, case-insensitive. Deleting a series keeps its slips, unfiled. `PUT /posts/:id/series` re-files a slip (⋯ menu → Move to series). Built so following + notifications can hang off the series page later.
- Tails are never shown on the tailer's profile; tracked for tail counts and per-poster tail records.
- Fades (`Fade` table, one per person per post; `POST/DELETE /posts/:id/fade`, list `GET /posts/:id/fades`): betting against a slip, no book link, personal slips only, never your own. A person tails or fades, never both: each route drops the other. While any bet is pending both can be undone (`DELETE /posts/:id/tail`); settled slips keep them. Once tailed, the card shows "Bet again" (reopens the book, no new tail) beside "✓ Tailed ✕". Fades don't feed any stats yet.
- Leagues: NFL, NCAA Football, NHL. Books: DraftKings, FanDuel, BetMGM, Caesars (`williamhill_us`), Fanatics, ESPN BET — stored in tables (seed in `prisma/seed.ts`).
- Only `SUPABASE_URL` and `SUPABASE_ANON_KEY` reach the browser (webpack DefinePlugin). Never import `src/server/*` from client code.

## Gotchas
- Prisma 7: migrations use `DIRECT_URL` (port 5432); runtime uses `DATABASE_URL` via `@prisma/adapter-pg` (`src/server/db.ts`). `migrate dev` doesn't auto-generate, hence the script. If `migrate dev` hangs, use `--create-only` then `prisma migrate deploy`. It also refuses to run non-interactively when a migration needs a confirmation (e.g. a new unique index); then write the SQL with `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script` into a new migration folder and `migrate deploy` it.
- npm `latest` for Prisma is an 8.x RC — stay on 7.10.0 until 8 is stable.
- The init migration revokes `anon`/`authenticated` access to `public` tables (keeps them off Supabase's Data API). Keep it that way; all data access goes through Express.
- Rewrite generated migrations that drop+add a column into a `RENAME` when renaming.
- ts-node uses a CommonJS override in `tsconfig.json`; client uses ESNext/bundler resolution.
- Webpack builds to `dist/client` (the only folder Express serves statically); tsc builds to `dist/server`, `dist/shared`, `dist/generated`. Never serve `dist/` itself — it would expose server code. The bundle is content-hashed (cached immutable); `index.html` is sent `no-cache`.
- helmet CSP allows the Supabase URL for `connect-src`/`img-src`; add any new external origins there.
- Windows dev machine (CRLF); Prettier uses `endOfLine: 'auto'`.

## Live odds (bet picker)
- `src/server/odds.ts` wraps The Odds API with an in-memory TTL cache; routes in `routes/odds.ts` (subscribers only). Market whitelist + labels live in `src/shared/markets.ts`.
- Live odds come from FanDuel only for now (`LIVE_ODDS_BOOK` in `shared/markets.ts`); the picker says so. Adding books costs nothing extra (≤10 books in one call = one region). Every slip comes from the picker (the typed-in form was removed), so FanDuel is the only book until more are added.
- In development (`nodemon.json` sets `NODE_ENV=development`) odds cache for 24h and persist to `.cache/odds/` (gitignored) so restarts don't spend credits; delete that folder to force fresh odds. nodemon only watches `src/server` and `src/shared`.
- Credits are scarce (shared key): in production game lines cache 5 min per league, props/alt lines cache 10 min per market and load one category at a time. Don't add eager or background fetches.
- Picked legs store `eventId`, `bookSelectionId` and the book's add-to-betslip `deepLink`; straight bets and ladder rungs also set `Bet.deepLink`. Older typed-in slips (no `eventId`/`deepLink`) still render; Tail sends them to the book's homepage. The server still accepts legs without links.
- Tail on a parlay (group ones too) is one link carrying every leg (`shared/betslip.ts`, `combinedSlipLink`): FanDuel's `addToBetslip?marketId[i]=…&selectionId[i]=…` loads them all onto one slip, and builds a same-game parlay at its own price when legs share a game (verified by hand 2026-10-20). Any leg without a FanDuel link falls back to the per-pick "Add" list. Ladder rungs keep the per-pick list (separate bets).

## Profile photos
- `src/server/avatars.ts`: a public Supabase Storage bucket 'avatars' (created on first upload), written only by the server with the admin key. `PUT /api/me/avatar` takes the raw image (type sniffed from the bytes, 1 MB cap), saves `<userId>/<timestamp>.<ext>` and stores the public URL in `User.avatarUrl`; `DELETE` clears it. Old files are removed best-effort. The browser center-crops and shrinks to a 256px JPEG first (`lib/avatar.ts`).
- `PersonRef` carries `avatarUrl`, so every person list (feed, comments, tailers, who's hot, earners, group legs) can show photos; render people with `components/UserAvatar` (photo, or the initial). Pick one at signup (optional, uploaded right after sign-in) or in Settings → Profile (`AvatarPicker`).
