# Tail-Me

Social sports-betting app for one friend group: users post straight / parlay / ladder slips, friends view and "tail" them (open the poster's sportsbook with the bet prefilled). $5/mo Stripe subscription pays for The Odds API.

## Stack
- Client: React 19 + TypeScript, react-router 7, Tailwind 3, bundled by webpack + Babel (`src/client`)
- Server: Express 5 (`src/server`), compiled by `tsc -p tsconfig.prod.json` to `dist/server`
- Shared: `src/shared` — odds math (`odds.ts`) and zod post schemas/types (`posts.ts`), used by both client and server
- DB: Supabase Postgres via **Prisma 7** (`prisma/schema.prisma`, config in `prisma.config.ts`, client generated to `src/generated/prisma`, gitignored)
- Auth: Supabase Auth; images will use Supabase Storage

## Commands
- `npm run start:dev` — API on :8080 (nodemon + ts-node); `npm run dev` — client on :4000, proxies `/api` to :8080
- `npm run prod` — build server + client, serve both from :8080
- `npm test` (vitest), `npm run typecheck`, `npm run lint`
- `npm run db:migrate` (migrate dev + generate), `db:deploy`, `db:seed`, `db:studio`
- `npm run db:demo` — fake friends + slips for UI work (re-runnable; `-- --clear` removes them)
- `npm run admin:set -- <username> [true|false]`, `npm run dev:subscribe -- <username> [ACTIVE|NONE]`

## Rules & decisions
- Paywall: free users can view + tail. Posting and anything that hits the Odds API require `requireSubscription`; client mirrors it with `useAuth().isSubscribed`. Both use `hasAccess` in `shared/billing.ts`: admins, ACTIVE / TRIALING / PAST_DUE (Stripe retrying the card), or everyone before `FREE_UNTIL` (launch promo, free through Oct 31 CT).
- Billing (`routes/billing.ts`, `server/stripe.ts`, page `/billing`): Stripe-hosted Checkout + billing portal only, so no card data or Stripe.js on our side. Status changes only via `syncCustomer`, which re-reads the customer's subscriptions from Stripe (never trusts event payloads or the success URL); called by the signed webhook `POST /api/billing/webhook` (mounted before `express.json` for the raw body, deduped in `StripeEvent`) and by `POST /api/billing/sync` on return from Checkout. Price comes from `STRIPE_PRICE_ID`, redirects from `APP_URL` (not the Host header). Subscribing during the promo sets a trial ending at `FREE_UNTIL` (`promoTrialEnd`). Webhook events needed: `checkout.session.completed`, `customer.subscription.created/updated/deleted`.
- Signed-out visitors at `/` see the marketing page (`pages/Landing.tsx`, rendered by `RequireAuth`); other protected routes still redirect to `/login`. Its slips are static mockups, so it makes no API calls.
- First-visit tour (`components/Tutorial.tsx`): a 7-step card carousel (feed, Tail, posting, ladders, group parlays, series, auto-grading) that `AppLayout` opens until `User.tutorialSeenAt` is set (`POST /api/me/tutorial`, on finish or skip); Settings → Help → "Take the tour" replays it (`openTour` on the layout context). Keep its copy in step with features. Empty spots show faded, "Example"-tagged placeholders (`components/Placeholders.tsx`): a sample straight, ladder and group parlay on an empty feed, ghost leaderboard rows, a 0-0 group parlay panel.
- Signup is server-side only (`POST /api/auth/signup`) so the shared `SIGNUP_PASSCODE` can't be skipped; Supabase public signups are meant to be disabled.
- API auth: client sends Supabase access token as `Authorization: Bearer`; `requireAuth` verifies it and loads the Prisma `User` into `req.user`.
- Users have required `fullName` + unique `username`; show both.
- Post model: Post -> Bet[] -> BetLeg[]. Straight/parlay = 1 bet; ladder = 1 single-leg bet per rung (same pick, climbing lines). Units on bets; 0 units is allowed (0–100; a blank box is an error, not 0); straight/parlay slips show "$10 pays $X" (`payout(10, decimalOdds)`; $0 once lost, $10 back on push/void). Ladders show payouts in the poster's units plus an "N/M hit" count. Parlay `americanOdds` may be the book's slip price (same-game parlays) instead of multiplied legs.
- Bets grade themselves (`src/server/grading.ts`, every 2 min, started in `index.ts`; `DISABLE_GRADER=true` turns it off). Pending legs on games that have started (up to 7 days back) are matched to ESPN's free, unofficial scoreboard (`src/server/espn.ts`): game lines grade from the final score, props from the box score (`BetLeg.actual` keeps the stat, shown as "Final 278"). While a game is on, `actual` holds the running stat (props) or combined score (totals), and only decided outcomes grade (`gradeLiveProp` / `gradeLiveGameLine`: an Under past its line loses, an Over past it or a scored Yes prop hits, totals the score passed; sides wait). Slips draw it as a short progress bar whose end is the line, so a cleared line reads full (`StatBar` / `legStatBar` in `SlipParts`; every ladder rung gets its own bar against its own line): Overs red until past the line then green, Unders green until past it then red, labeled LIVE or FINAL; those AUTO marks on not-yet-completed events are provisional and re-checked every run until the final (yardage can dip back). Live ESPN data caches 2 min. Feed cards with a game on (or over and ungraded), and unsettled group parlays (friends keep adding legs), reload every 2 min via `GET /posts/refresh?ids=` (`PostList`). The feed also passes the side panels' posts to `PostList updates`, which swaps them into matching cards as they arrive, so a panel never shows a leg or result its card doesn't. Pages refresh quietly with `lib/useAutoRefresh` (every 2 min while the tab is visible, and at once on returning to it): feed cards, the side panels and stats, profiles and Records all swap fresh data in place with no loading state, so nobody loses their spot. Don't add a refresh that clears data first. Rules + name matching live in `shared/grading.ts`. Leg results roll up via `betResultFromLegs` (parlays use `groupResult`). Postponed/canceled games void. Unmatched games or players (incl. players who sat) stay pending for a person. `gradedBy` (AUTO/MANUAL) on Bet and BetLeg: the grader never touches MANUAL; filter with `OR [null, AUTO]`, not `not: 'MANUAL'` (NULLs). Manual override is subtle on purpose: the ⋯ menu's "Change result" (`SlipMenu`) for personal slips, a small pencil on group legs. One shared feed.
- Slip status chips (`shared/live.ts`, `SlipParts`): settled bets show their result; unsettled ones show LIVE while the game is on (once on the slip when every leg is the same game, else per leg beside the game), PENDING only once the game is over but ungraded, and nothing before kickoff. A game counts as over when the grader marked its `Event` completed or 5h after start (`MAX_GAME_MS`). Legs carry `eventId`/`startsAt`/`gameFinal` for this; cards tick once a minute (`useNow`). Started games also carry `score` (away-home + a short clock, `Event.statusDetail`: "Q3 4:12", "Half", "P2 08:41", "Final", from `gameClock` in `shared/live.ts`), refreshed every grader run by `refreshLiveScores` for every live game with a leg on it (it never marks games complete; `runGrading` does). Slips show it beside the game (`GameScore`: red pulsing "14-10 · Q3 4:12" live, gray "Final 24-17" after), and it stands in for the LIVE chip wherever there's a score; LIVE only shows for a game with no score yet. Group legs show a green check / red X on the right as their one result mark. Picks posted after kickoff carry a permanent amber "In-game" chip (`inGameMinutes`, `InGameBadge`; tooltip says how far in) on the slip, and per leg on multi-game parlays; group parlay legs have no add time yet so they don't get it.
- Editing (`PUT /posts/:id`, `editPostSchema` + `canEditSlip` in `shared/posts.ts`, ⋯ menu → Edit slip): straights and parlays only, by the author, until any of their games starts (and nothing graded). Opens the composer on review with the posted legs (`legToSelection`, kept at their posted prices; matched to live odds by `matchesPick` since stored props are `player_prop` + label). Legs can be removed or added (new ones from live odds, games not started); 1 leg = straight, 2+ = parlay; units, caption and the book's price can change. No Edited tag (user's call). Odds are always editable by the author on every slip type (⋯ → Change odds, `PUT /posts/bets/:betId/odds`), even after kickoff or settling, because our parlay math can't match the book's price; one-leg bets update their leg too; on an open group parlay adding or removing a leg resets it to the legs multiplied. Any parlay (not just SGPs) can carry the book's price (`slipOdds`) when posting or editing. Units are likewise always editable by the author on personal slips (⋯ → Change units, `PUT /posts/bets/:betId/units`, `betUnitsSchema`; per rung on ladders), so they move stats after settling too.
- Deleting can't clean up a record (`deleteRule` in `shared/posts.ts`): settled slips are soft-deleted (hidden from feeds, can't be re-graded) and still count in every stat (profiles, streaks, earners, calendar, series, group record); unsettled slips can only be deleted within `DELETE_GRACE_MINUTES` (15) of posting, which removes them entirely; unlocked group parlays can always be removed. Stats queries must not filter on `deletedAt`; feed/list queries must. The delete dialog explains this first. Author actions (move to series, delete) live in the card's ⋯ menu (`SlipMenu`). The menu never hides a rule: Edit slip / Add rung / Delete stay listed, greyed with a 🔒 and the reason once locked ("Locked at kickoff", "Locked once graded", "Settle it first (15 min passed)"), and otherwise carry a hint ("Until 7:20 PM CT", "12 min left", "Still counts in stats"); `lib/slipActions.ts` wraps the shared rules for this. The "Slip posted" toast says the same in one line (toasts take an optional `detail` second line).
- Admin moderation: admins get the ⋯ menu on everyone's slips (tagged "Admin · <name>'s slip"): edit, odds, units, result, delete, but not Move to series (series are the poster's). `canEditSlip` / `deleteRule` take an `asAdmin` flag: admins can edit any straight/parlay any time, graded or not (and add started games' legs); when the legs change, the bet's result is re-derived from them (`betResultFromLegs`; PENDING goes back to the grader, else MANUAL). Delete is never blocked (unsettled = removed; settled still only hidden, so records stand). They can also grade any group parlay leg. Server routes check `req.user.isAdmin` alongside the author check.
- Admin page (`/admin`, `pages/Admin.tsx`, linked from the account menus for admins only; non-admins are redirected to `/`): tiles for total users and subscribed (paying = `isPaid`: ACTIVE / TRIALING / PAST_DUE, with trial / past due / canceling counts), and a Subscribed / All users list with plan chips and renew / end dates. Data from `GET /api/admin/users` (`routes/admin.ts`, behind `requireAdmin`); types and `userCounts` in `shared/admin.ts`. Admin views and tools go here.
- Dev-only "View as regular user" (`lib/viewAs.ts`): a switch in the account menus for admins (amber, plus a "Back to admin" banner while on) stores a localStorage flag; `api.ts` then sends `X-View-As: user`, and `requireAuth` drops `isAdmin` for that request only when `NODE_ENV === 'development'`, so `/api/me`, menus and server permissions all act like a normal account. Production builds compile it out (webpack `--mode`) and the production server ignores the header. It doesn't touch subscription status: during the promo everyone can post anyway; use `npm run dev:subscribe` to test the paywall.
- Ladder rungs can be added after posting (⋯ → Add rung, `POST /posts/:id/rungs`, `canAddRung` / `nextRung` / `addRungSchema` in `shared/posts.ts`): the author pregame only (nothing graded, no game started), admins any time, max `LADDER_MAX_RUNGS` (10). The line starts one step past the longest-priced rung (step = gap between the two longest prices; − / + nudge by it), the user types the odds; units default to that rung's. The new rung copies the ladder's pick, has no book link, and rungs are renumbered by line. The grader picks it up like any rung.
- The site runs on Central time (`shared/time.ts`, `America/Chicago`): every shown date/time and every day bucket (calendar, "Today") uses it regardless of the viewer's device; clock times carry a "CT" label. Format with `inSiteZone(...)`, never bare `toLocale*`; the lock-by input uses `toSiteInput` / `fromSiteInput`.
- Stats (`src/shared/stats.ts`, served by `GET /api/users/:username?range=7d|30d|all`) count bets: straight/parlay = 1, every ladder rung is its own W/L. Voids don't count. Multi-league parlays count overall and per type but under no league. Pushes don't break streaks; current streak ignores the date range. Computed in memory per request (fine at friend-group size).
- Profiles live at `/u/:username`: date range is the only filter; per-type / per-league stats are compact rows in a sticky side column on `lg`; on smaller screens they're one tabbed card (Bet type, the default / Series / League) above the slips. `AppLayout` main is `max-w-5xl`; each page sets its own column width (feed = `max-w-2xl`). `GET /api/posts?author=&range=` feeds their slip list. `PATCH /api/me` edits name + bio (username is fixed). Settings (`/settings`, `pages/Settings.tsx`) is the one place to edit your account: name + bio, email + change password (re-checks the current password with Supabase, then `updateUser`), dark mode, a plan summary linking to `/billing`, Take the tour, sign out. The account menus hold Profile, Settings, the dark mode switch and Sign out; the profile page's "Edit profile" links there.
- Social (`routes/social.ts`, mounted at `/api`): `GET /posts/:id/tails` (who tailed, once per person), `POST /posts/:id/reactions {emoji}` toggles any standard emoji: the server checks it against the Unicode list up to `EMOJI_MAX_VERSION` (16.0), base emoji only, no skin tones (`server/emoji.ts`, from the `unicode-emoji-json` package). The picker (`components/EmojiPicker.tsx`) is paged like the iOS keyboard: page one is the 42 quick reactions, six rows of seven by mood (`REACTION_EMOJIS`, with names in `REACTION_LABELS`), then a page per Unicode category; the list is a separate bundle chunk loaded when the picker first opens. Slips order reactions quick ones first, then by count (`orderReactions`, used by server and client), comments `GET/POST /posts/:id/comments`, `DELETE /comments/:id` (own, or admin), `PUT /comments/:id/vote {value: 1|-1|0}` (`CommentVote` table). Free users can do all of it.
- Badges (`shared/badges.ts`): poster streak chip at W3+ (`FeedPost.author.streak`, all-time), win tiers by the longest price that hit (`WIN_TIERS`: Nice hit +200 green, Cashed +400 gold, Big score +900 violet, Jackpot +2400 pink with a shimmer; a clean ladder sweep shows at least Cashed) set the card border and a banner (`TIER_STYLES`, `WinBanner` in `SlipSocial`), "🔒 Group lock" at 3+ tails (`CrowdChip`). Cards show the latest 3 tailers' faces + count (`FeedPost.tailers`, distinct people). Thresholds live there. Settling returns the updated `FeedPost` so streaks refresh.
- Feed sidebar (`GET /api/community?tz=&month=YYYY-MM`, on `lg` the side column holds top earners, group parlays (`CommunityHighlights stacked`), who's hot and the calendar; below `lg` top earners, the group record and the calendar are one tabbed card above the slips (`CommunityTabs`); one fetch via `useCommunityStats`): "Who's hot" (W3+ streaks), top 3 earners over 7 days (only people up units), month calendar of group net units by post day in the viewer's time zone. Each day square shows the date small at the top and the day's net units centered (`dayUnits`: one decimal under 10, whole from 10, no "u"), colored green / red, darker past `BIG_DAY_UNITS`.
- Feed filters (underlined tabs above the slips, `FilterTabs` in `Feed.tsx`, on a fixed-height row the side columns offset by `mt-12`, never scrolling; `GET /posts?status=`, `FEED_FILTERS` in `shared/posts.ts`): Open (default: any bet pending), Live (a leg's game is on, same rule as LIVE tags), Won / Lost (settled; one-bet slips by their result, ladders by final net units via the raw-SQL `settledLadderIds`: up is Won, down is Lost, and at exactly even (0-unit ladders) more hits than misses is Won and the reverse Lost), All. Empty filters say so with a "See all slips" link. A side-panel click on a slip outside the filter retries under All. Profiles and series pages don't filter. `PostList` ignores out-of-date responses (`latest` / `loadedFor`).
- Today strip (`TodayStrip` in `CommunitySidebar.tsx`, top of the feed on every screen, from `CommunityStats.today` / `daySuperlatives` in `shared/community.ts`): settled bets on today's games give (a bet's day is the CT day of its last game, `gameDay`, so late games graded after midnight count for the night they were played; no game attached falls back to the post day) 💰 Biggest hit, 📈 Top earner, 💔 Worst beat (3+ leg parlay lost on one leg) and 📉 Rough day, each only when someone qualifies; hidden when none do. 2 columns on phones, up to 4 wider. When it shows, the side columns line up with it (no `mt-12`).
- Feed left column (`xl` only, `components/ActivePanels.tsx`, `GET /api/posts/active`, refreshed every 2 min): "Active group parlays" (unsettled, or settled since midnight CT), each with its own emoji tile (unique within the list) and a status chip that's always there (OPEN + lock time, LOCKED + first start, LIVE / PENDING + legs hit, HIT / BUSTED), and "Live now" (personal slips with a game on, settled or not, so a mid-game bust shows; BUSTED / HIT / LIVE + legs or rungs hit). Clicking a row scrolls the feed to the slip (`PostList focusId` pages down up to 10 pages, `lib/scrollToSlip` flashes a ring; cards carry `id="slip-<postId>"`). Below `xl` the group parlays panel sits above the slips only when there are any.
- Group parlays (`GROUP_PARLAY` post, one Bet): each person adds one leg (`BetLeg.addedById`, unique per bet; one leg per market, `legMarketSlot` in `shared/posts.ts`: a game's moneyline / spread / total, or a player's stat, any side or line, since FanDuel won't parlay two from one market; the server refuses with "<market> is already <name>'s leg" and the join picker grays those prices out showing whose they are, via `JoinTarget.taken` + `TakenContext`) via `POST /posts/:id/legs` until `Post.lockAt` passes or the creator hits `POST /posts/:id/lock` (needs 2+ legs). Legs come from the live picker only (one book). The creator can tick "Same game parlay (SGP)" (the card then shows "🎯 <game> SGP") (`Post.groupEventId` / `groupEventLabel`, from their leg); joins must match that event id; the picker opens straight into that game with no way back to other games (the server check is the fail-safe). Same-game group parlays show the legs multiplied as "est." until the creator enters the book's price after lock (`PUT /posts/:id/price`); `hasBookPrice` tells them apart (legs are fixed once locked). Once locked anyone, creator included, can place it (the tail route). Legs are graded one by one (`PATCH /posts/legs/:legId`, owner or creator); `groupResult` derives the bet. They never count toward personal stats, streaks, earners or the calendar (`PostType` in `shared/stats.ts` excludes them; filter with `POST_TYPES` / `isPersonalType`). The sidebar shows the group record and each person's legs hit / graded (a Top / Bottom pickers toggle ranking by hit rate, `rankPickers`; each shows its half of the group, at most 5, so nobody is in both, then "See all"), plus a 💀 tally of parlays that lost on their leg alone (`groupRow`'s `onlyMiss`, same as Records). Adding legs needs a subscription; placing doesn't.
- Series (`Series` table, `Post.seriesId`, `shared/series.ts`, `routes/series.ts`): a user's named run of personal slips (never group parlays), picked on the slip review step or created there. Listed in the profile side column (`SeriesPanel`), each with a page at `/u/:username/s/:id` showing its record (same stats math as profiles) and slips (`GET /posts?series=`). Names unique per owner, case-insensitive. Each has a cover: an emoji from `SERIES_EMOJIS` on a color from `SERIES_COLORS` (defaults 📚 + emerald), picked when starting one from the profile panel or editing it on its page (the review step's quick create takes the defaults); render with `SeriesBadge` (`components/SeriesCover.tsx`). Deleting a series keeps its slips, unfiled. `PUT /posts/:id/series` re-files a slip (⋯ menu → Move to series). Built so following + notifications can hang off the series page later.
- One-leg misses (`isOneLegMiss` / `nearMisses` in `shared/records.ts`): a parlay that lost on exactly one leg (pushed / voided legs don't count against it). Profiles show "💔 Missed by one leg: N parlays · +Xu left on the table" (what they'd have won, in the poster's units, for the profile's range; `UserProfile.nearMisses`); Records has a sortable "1-leg misses" column, and its Group parlays tab a card with the group's one-leg misses, what $10 on each would have paid, and the top 3 culprits by sole misses.
- User search (`components/UserSearch.tsx`, beside the nav links on md+; on phones a 🔍 button by ☰ opens a full-width search row under the header (`openMenu === 'search'`), focused, with 16px text so iOS doesn't zoom): a combobox that asks `GET /api/users?q=` 150ms after typing stops (name or username contains, any case; up to 8, prefix matches first) and drops down photo + name + @username; arrows / Enter / Escape, a click opens `/u/:username`.
- Records page (`/records`, `pages/Records.tsx`, `GET /api/records?range=`, math in `shared/records.ts`; nav item next to Feed): everyone's personal record side by side (record, win %, units, ROI, L5, streak, best streak, Faders = how the people who faded them did, once per fader (a fade wins when they lose)), sortable by clicking column headers; tables at every width, phones scroll the stats sideways under a pinned name column (nothing truncated); headers never wrap, and tables show first names only (`firstName`). Win % / ROI only rank after `MIN_RANKED` (10) settled bets; L5 and streaks ignore the range. A Series tab: every user's series (cover, name linking to its page, "by <owner>") with record, win %, units, ROI, L5, streak, best and slips, sortable like the leaderboard (`RecordsPage.series`, `RecordBet.seriesId`). A Group parlays tab: group record plus each person's legs (parlays joined, hit, busted, hit %, 💀 Only miss = theirs was the only losing leg, cashed, L5 legs). Superlatives on top, each shown only once someone qualifies, in `SUPERLATIVE_ORDER` (brags first, roasts last): biggest hit, best to tail, best tailer, longest streak, best CT day, sharpest (win %, 10+ bets), longest parlay hit, ladder king (clean sweeps), most tailed, group parlay MVP, most active, worst beat (3+ leg parlay lost on one leg), so close (one-leg misses), coldest streak (L3+), worst day, fade material (lowest win %, 10+ bets, under 50%). They live in their own Awards tab (after Leaderboard, Group parlays, Series), every card shown, 2 across on phones and 3 wider. Same counting as profiles; group parlays never mix into personal numbers.
- Tails are never shown on the tailer's profile; tracked for tail counts (Records' "Most tailed") the profile's "Tailed" tile (count, by how many people). What tailing made people is in units, assuming each tailer bet the poster's units (real stakes aren't known): every tail of a settled bet adds that bet's net. Settled slips show "+3.48u for tailers" (all tailers combined) beside their tailers, and Records has a 💸 "Best to tail" superlative (made the most for others) and a 🧲 "Best tailer" one (made the most tailing others: each settled bet a person tailed adds its net, `RecordBet.tailers`). A line on the profile was tried and dropped; no W-L records for tails.
- Fades (`Fade` table, one per person per post; `POST/DELETE /posts/:id/fade`, list `GET /posts/:id/fades`): betting against a slip, no book link, straight bets only and not one-sided props like Anytime TD / Anytime Goal, which are stored as `player_prop` with selection "Yes" (`canBeFaded` in `shared/posts.ts`, checked on `POST` only so older fades can still be undone), never your own. A person tails or fades, never both: each route drops the other. While any bet is pending both can be undone (`DELETE /posts/:id/tail`); settled slips keep them. Once tailed, the card shows "Bet again" (reopens the book, no new tail) beside "✓ Tailed ✕". Fades don't feed any stats yet.
- Leagues: NFL, NCAA Football, NBA, NHL, UFC (`mma_mixed_martial_arts`: moneyline only via `gameMarkets` / `isFight` in `shared/markets.ts`, matchups read "A vs B" (`matchupLabel`), no props or tabs; ESPN `mma/ufc` cards are split into one game per bout scored 1-0 for the winner (a draw is 0-0, a push), matched either way round (`findGame` flips), clock "R2 3:12" and no score on slips. picker tab order `SPORT_ORDER` in `shared/markets.ts`; profiles list them A-Z from `/api/meta`). Team totals (`team_totals` + `alternate_team_totals`, every team sport's "Team Totals" tab, and alternates also in Alt Lines grouped by team and side; `marketLabel` pins both keys to the one label. FanDuel posts some games' team totals only as alts, so the tab also loads `alternate_team_totals` (`altFallback`) and, when the main market is empty, shows each team's most evenly priced alt line (`mainLinesFromAlts` in `lib/slip.ts`), picked as that alt. Alt team totals show as one section per team ("<Team> Alt Team Total", Over / Under rows) in both the Team Totals tab (below the main lines, which drop their per-row alt link) and Alt Lines, for every team sport) ride the prop path as `player_prop` with label `TEAM_TOTAL_LABEL` and the team as `playerName`; the grader scores them from that team's score (`teamScore`), live too. NBA props: points, rebounds, assists, made threes, combos (PRA, P+R, P+A, R+A), steals, blocks, double/triple-double (Yes props); graded from ESPN `basketball/nba` box scores (`BASKETBALL_COLUMNS`; DNPs have no stats and are skipped so their props wait for a person; combos and doubles come from `withBasketballTotals`). Books: DraftKings, FanDuel, BetMGM, Caesars (`williamhill_us`), Fanatics, ESPN BET — stored in tables (seed in `prisma/seed.ts`).
- Only `SUPABASE_URL` and `SUPABASE_ANON_KEY` reach the browser (webpack DefinePlugin). Never import `src/server/*` from client code.

## Gotchas
- Prisma 7: migrations use `DIRECT_URL` (port 5432); runtime uses `DATABASE_URL` via `@prisma/adapter-pg` (`src/server/db.ts`). `migrate dev` doesn't auto-generate, hence the script. If `migrate dev` hangs, use `--create-only` then `prisma migrate deploy`. It also refuses to run non-interactively when a migration needs a confirmation (e.g. a new unique index); then write the SQL with `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script` into a new migration folder and `migrate deploy` it.
- npm `latest` for Prisma is an 8.x RC — stay on 7.10.0 until 8 is stable.
- The init migration revokes `anon`/`authenticated` access to `public` tables (keeps them off Supabase's Data API). Keep it that way; all data access goes through Express.
- Rewrite generated migrations that drop+add a column into a `RENAME` when renaming.
- ts-node uses a CommonJS override in `tsconfig.json`; client uses ESNext/bundler resolution.
- Webpack builds to `dist/client` (the only folder Express serves statically); tsc builds to `dist/server`, `dist/shared`, `dist/generated`. Never serve `dist/` itself — it would expose server code. The bundle is content-hashed (cached immutable); `index.html` is sent `no-cache`.
- helmet CSP allows the Supabase URL for `connect-src`/`img-src`; add any new external origins there.
- iOS Safari zooms into any text field under 16px and stays zoomed. `main.css` forces 16px on every input / textarea / select below 768px (with !important, over text-sm), so don't fight it with per-field sizes; posting a comment also blurs the field to drop the keyboard.

## Installable app + push notifications
- The site is a PWA: `src/client/public/` (manifest, `sw.js`, icons from the wordmark colors) is copied into `dist/client` by webpack's CopyPlugin at fixed URLs. `sw.js` caches nothing (odds/scores must stay fresh); it only shows pushes and routes taps: an open window gets a `postMessage` that `App` navigates with, else it opens the URL. Taps land on `/?slip=<id>` (`slipUrl`), which the feed opens under All. `lib/theme` keeps `<meta name="theme-color">` in step with dark mode. Status bar style is `default` (translucent draws white text, unreadable on the light theme); the header and phone composer still pad with `env(safe-area-inset-*)`.
- Web Push via `web-push` with VAPID keys (`VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT`; without them nothing sends and Settings says so). The public key reaches the browser from `GET /api/me/notifications`, not webpack. Anything sharing a database must use the same pair, or saved subscriptions stop working. iPhones only get push in the home-screen app (iOS 16.4+); Settings → Notifications shows Add to Home Screen steps there (`pushSupport()` = 'needs-install'), and Get the app offers Android's install prompt. The first time the home-screen app opens (after the tour, permission not yet asked, not subscribed), `components/NotificationPrompt` pops up "Turn on notifications?"; its button asks permission (iOS only allows that from a tap). Once per device (`tailme-push-asked` in localStorage), whatever they pick.
- `PushSubscription` (one per device, endpoint unique, moves to whoever subscribes on it; deleted on 404/410 and on sign-out). `User.notifyPrefs` stores only switches changed from `NOTIFY_DEFAULTS` (`shared/notifications.ts`: slips, groups, tails, comments, reactions (off by default), results). `server/push.ts` sends (`notify` / `notifyEveryone`, never throw); `server/notices.ts` says who hears what, fired after the response without awaiting: new slip → everyone (filed under a series it reads "Charlie posted the CharLadder", `newSlipTitle`); group parlay started → everyone, joined → creator, ⏰ `GROUP_REMINDER_MINUTES` (60) before lock → everyone without a leg (once, `Post.lockReminderAt`, from the grader loop); first tail / fade → poster (no group parlays); comment → the poster only (not others in the thread, user's call); reaction added → poster; settled (pending → result, by the grader or by hand; ladders once every rung is in) → poster + tailers, or everyone in a group parlay, never the person who graded it. Wording lives in `shared/notifications.ts`. Settings has a "Send a test" button (`POST /api/me/push/test`, ignores the switches).

## Live odds (bet picker)
- `src/server/odds.ts` wraps The Odds API with an in-memory TTL cache; routes in `routes/odds.ts` (subscribers only). Market whitelist + labels live in `src/shared/markets.ts`.
- Live odds come from FanDuel only for now (`LIVE_ODDS_BOOK` in `shared/markets.ts`); the picker says so. Adding books costs nothing extra (≤10 books in one call = one region). Every slip comes from the picker (the typed-in form was removed), so FanDuel is the only book until more are added.
- In development (`nodemon.json` sets `NODE_ENV=development`) odds cache for 24h and persist to `.cache/odds/` (gitignored) so restarts don't spend credits; delete that folder to force fresh odds. nodemon only watches `src/server` and `src/shared`.
- Credits are scarce (shared key): in production game lines cache 5 min per league, props/alt lines cache 10 min per market and load one category at a time. Don't add eager or background fetches.
- Picked legs store `eventId`, `bookSelectionId` and the book's add-to-betslip `deepLink`; straight bets and ladder rungs also set `Bet.deepLink`. Older typed-in slips (no `eventId`/`deepLink`) still render; Tail sends them to the book's homepage. The server still accepts legs without links.
- Paste a link (`components/SlipImport.tsx`, `POST /api/odds/import`, `shared/slipImport.ts`): New slip can be built from a FanDuel share link (`addToBetslip?shareCode=…`) or add-to-betslip link. Share codes decode via FanDuel's unofficial, login-free `share-bet/decode-short-url` endpoint (`server/fanduelShare.ts`, cached 10 min, the sharer's customer id is dropped); it can break any time, so failures say "pick the legs instead". Picks are `marketId`+`selectionId` pairs matched against our odds' outcome links: game lines from the leagues' cached games, props by loading a game's picker markets (~17 credits, cached 10 min): the first paste tries up to `AUTO_GUESS_GAMES` (3) games ranked by how close their FanDuel market ids sit to the picks' (`rankGamesByMarketId`, an unverified guess; logged as "Slip import: …"), then asks "which game?" (league-grouped list + team search), sending back `searched` ids so earlier finds keep counting. Picks land at FanDuel's current price. Not offered for group parlays or editing.
- Tail on a parlay (group ones too) is one link carrying every leg (`shared/betslip.ts`, `combinedSlipLink`): FanDuel's `addToBetslip?marketId[i]=…&selectionId[i]=…` loads them all onto one slip, and builds a same-game parlay at its own price when legs share a game (verified by hand 2026-10-20). Any leg without a FanDuel link falls back to the per-pick "Add" list. Ladder rungs keep the per-pick list (separate bets).

## Profile photos
- `src/server/avatars.ts`: a public Supabase Storage bucket 'avatars' (created on first upload), written only by the server with the admin key. `PUT /api/me/avatar` takes the raw image (type sniffed from the bytes, 1 MB cap), saves `<userId>/<timestamp>.<ext>` and stores the public URL in `User.avatarUrl`; `DELETE` clears it. Old files are removed best-effort. The browser center-crops and shrinks to a 256px JPEG first (`lib/avatar.ts`).
- `PersonRef` carries `avatarUrl`, so every person list (feed, comments, tailers, who's hot, earners, group legs) can show photos; render people with `components/UserAvatar` (photo, or the initial). Pick one at signup (optional, uploaded right after sign-in) or in Settings → Profile (`AvatarPicker`).
- No photo: a monogram (first initial) on `User.avatarColor`, a `SERIES_COLORS` key (default emerald). `PersonRef` carries it too; pass `color` to `UserAvatar`. `AvatarPicker` shows the swatches (`components/ColorSwatches`, the palette shared with series covers) only while there's no photo; Settings saves a pick at once via `PATCH /api/me {avatarColor}`, signup sends it right after sign-in.
